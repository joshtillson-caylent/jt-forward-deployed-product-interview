# First 30 Days — Sequence and Rationale

Sequenced from `discovery/align/value-charter.md`'s value levers and `.claude/skills/genai-poc-strategy`'s build-sequence logic (dependencies first, a lighthouse use case early for confidence, generalize only after it's proven) — adapted for a trust-building engagement, not a technical POC.

## Week 1 — Discovery + a shadowed real task

- Run the kickoff session designed in `discovery/discovery-session-design.md`: live walkthrough of a real recent task, plus the draft-then-verify demo in the room.
- **Why first:** everything downstream — the lighthouse use case, the trust model, David's two-week win — depends on evidence from a real task, not an assumed one. Skipping this and jumping to "here's a use case" would repeat the orientation's mistake.

## Week 2 — Synthesis + lighthouse use case selection (with David)

- Turn the kickoff session into updated `discovery/align/*` documents (replace `hypothesis — validate` labels with what was actually said).
- Select the lighthouse use case **with David, not for him** — the one task from the walkthrough that's mechanical enough to show fast time savings and low-stakes enough that a mistake doesn't reach the board undetected.
- Give David the board-ready language from `deliverables/david-okafor-first-two-weeks.md`.
- **Why second:** this is the two-week mark the brief's own deck topic asks about — David needs something concrete by here, and a use case chosen jointly is one he'll actually defend, versus one handed to him.

## Weeks 3-4 — Small guided pilot (1-2 analysts) + checkpoint readout

- Run the lighthouse use case as a real, small pilot with the two analysts already in the room from kickoff — draft-then-verify on their actual work, not a synthetic example.
- Capture what changed: time saved, what the analyst still caught that a draft missed, anything that broke the trust model in practice.
- Prepare a checkpoint readout for the PE sponsor: real evidence, not license-utilization metrics — this is the first artifact that speaks in the PE sponsor's terms rather than David's.
- **Why last:** a pilot run before the lighthouse use case is confirmed risks generalizing from the wrong task; running it with the same two analysts from kickoff (rather than new people) keeps the trust built in week 1 intact instead of starting cold with strangers.

## What happens after day 30 (not yet in scope)

Whether/how this generalizes to the remaining 6 analysts is a decision for the checkpoint readout, not this plan — the value charter's scalability lever exists precisely so that decision has a lens to be made against, once there's real pilot evidence to look at.
