# Interview Guide

Create structured interview guides for user research, customer discovery, and stakeholder interviews.

## Optional MCP integrations

- **Google Drive** — search for prior interview guides on the same problem space and reuse / iterate rather than starting from scratch. Optionally save the finished guide to a designated research folder.
- **`meeting-notes/`** (always on disk) — pull prior customer call notes to surface what's already been asked and what's still unknown. Avoid re-asking questions the team already has answers to.
- **Google Calendar** — if the interview is already scheduled, pull the event metadata (time, attendee, duration) to size the guide correctly.

Gracefully degrade: if no MCPs are connected, run as today.

## Workflow

### Phase 1: Interview Context
- What is the research objective? What decision will this inform?
- Who is the interviewee? (user persona, role, relationship to product)
- What do we already know? What are our hypotheses?
- What are the biggest unknowns we need to reduce?
- Interview format: in-person, video, phone? How long?

### Phase 2: Guide Structure

**Opening (5 min)**
- Warm-up and rapport building
- Explain the purpose (without biasing)
- Set expectations (no wrong answers, we're learning)
- Ask permission to record

**Context Questions (10 min)**
- Role, responsibilities, and day-to-day
- Relationship to the problem space
- Current tools and workflows

**Core Questions (20-30 min)**
- Open-ended questions about the problem area
- Follow-up probes for depth ("Tell me more about...", "Can you walk me through the last time...?", "What happened next?")
- Scenario-based questions ("Imagine you needed to... how would you approach it?")
- Pain point exploration ("What's the hardest part about...?")

**Solution Exploration (10 min)** *(if appropriate)*
- Show concepts, prototypes, or descriptions
- Observe reactions before asking questions
- "What would you expect to happen if you clicked here?"
- "How would this fit into your current workflow?"

**Closing (5 min)**
- "Is there anything I didn't ask that I should have?"
- "Who else should I talk to about this?"
- Thank them and explain next steps

### Phase 3: Question Design Principles
- **Open-ended:** Avoid yes/no questions. Start with "how," "what," "tell me about"
- **Non-leading:** Don't telegraph the desired answer
- **Specific:** Ask about concrete past experiences, not hypothetical futures
- **Layered:** Start broad, then probe deeper on interesting threads
- **Behavioral:** Focus on what people do, not what they say they'd do

### Phase 4: Analysis Framework
- Key themes to listen for during the interview
- Signals that confirm or challenge our hypotheses
- Quotes to capture verbatim
- Synthesis template for post-interview notes

### Phase 5: Output

**Interview guide containing:**
1. Research objective and hypotheses
2. Interviewee profile/persona
3. Full question guide with probes (time-boxed sections)
4. Do's and don'ts for the interviewer
5. Analysis framework and synthesis template
6. Post-interview action items template
