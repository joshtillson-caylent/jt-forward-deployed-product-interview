# Service

The P3 layer: what turns the workflows in `build/` into an AI-enabled service the client runs. `build/` covers how each workflow works. This folder covers how the service is delivered, owned, governed, and kept healthy once Caylent steps back.

| File | What it is |
|------|-----------|
| `service-blueprint.md` | The service end to end: who it serves, what Claude does at each step, where people stay in the loop |
| `operating-model.md` | Who owns and runs it after handoff, and how it changes |
| `governance.md` | Policies, approval gates, change control, risks, audit, incidents |
| `run-and-monitor.md` | Production metrics, evals in production, alerting, cost, runbooks |
| `maturity-roadmap.md` | Where the client is on P1 → P3, and what comes next |
